# Душа компании

## Корпоративные видеовстречи в браузере — часть «Души Компании».

Перейдите к встрече из «Души Компании», введите имя и нажмите **«Набрать»**. Без отдельной регистрации в видеосервисе и установки приложений.

«Душа компании» использует WebRTC для передачи аудио и видео между участниками. Сервер создаёт конференции, хранит их в SQLite и обеспечивает обмен сигналами. Медиа передаются напрямую, а при настроенном TURN могут идти через ретранслятор. Групповые звонки используют mesh: нагрузка на сеть и устройства растёт с числом участников.

### Возможности

- **Вход по приглашению:** кнопка «Присоединиться» в «Душе Компании» открывает нужную конференцию.
- **Подготовка перед звонком:** имя, предпросмотр камеры, включение и отключение камеры и микрофона.
- **Видеосвязь WebRTC:** прямые соединения между участниками с поддержкой STUN/TURN.
- **Демонстрация экрана:** отдельная кнопка в панели звонка для запуска и остановки показа.
- **Корпоративный интерфейс:** светлый фон, компактные элементы управления и скругление самого изображения камеры.
- **Управляемые конференции:** создание через защищённый API, проверка существования и срока действия ссылки.
- **Временные TURN-пароли:** общий секрет остаётся на сервере; браузер получает ограниченные по времени credentials.

Создание и список встреч находятся в «Душе Компании». Корневая страница видеосервиса содержит только подсказку о входе. Кнопки чата в интерфейсе звонка нет.

## Запуск

Локально проверено на **Node.js 20.20.2**. В проекте используется `better-sqlite3 9.6.0`: на другой версии Node.js может потребоваться сборка нативного модуля.

```sh
npm ci
npm start
```

Перед запуском передайте переменные окружения из таблицы ниже. Само приложение не загружает `.env`; Docker Compose читает его через `env_file`.

По умолчанию сервер работает на порту `824`. Для доступа только с текущего компьютера задайте `HOST=127.0.0.1`. Для камеры и микрофона вне localhost требуется HTTPS.

### Настройки

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | Порт приложения | `824` |
| `HOST` | Адрес прослушивания; для локальной проверки `127.0.0.1` | Все интерфейсы |
| `CORS_ORIGIN` | Разрешённые origin через запятую | `http://localhost:824` |
| `BOT_API_SECRET` | Секрет вызывающей системы для создания конференций | Не задан |
| `DB_PATH` | Путь к SQLite внутри приложения | `./data/naberesh.db` |
| `APP_DATA_DIR` | Каталог хоста, который Compose монтирует в `/app/data` | `./persistent-data` |
| `CONFERENCE_TTL_MINUTES` | Срок доступности конференции в минутах | Не ограничен |
| `TURN_HOST` | Адрес TURN-сервера | `DOMAIN` или `localhost` |
| `TURN_SECRET` | Общий секрет приложения и coturn | Не задан |
| `TURN_URLS` | Адреса TURN через запятую | UDP/TCP 3478 и TLS/TCP 5349 на `TURN_HOST` |
| `TURN_TTL` | Срок действия TURN credentials в секундах | `86400` |

## API создания конференций

Конференции создаёт «Душа Компании» или бот через серверную интеграцию. Секрет API нельзя размещать в браузерном коде.

`POST /api/createConference`

Заголовки:

```text
Content-Type: application/json
X-Bot-Secret: <BOT_API_SECRET>
```

Тело запроса:

```json
{
  "telegramUserId": "123456789",
  "metadata": { "note": "Встреча команды" }
}
```

Ответ `201`:

```json
{
  "id": "<generated-id>",
  "url": "https://host/<generated-id>"
}
```

- `telegramUserId` — обязательная непустая строка; название поля сохранено для совместимости.
- `metadata` — необязательные данные конференции.
- Неверный или отсутствующий секрет возвращает `401`; некорректное тело — `400`.
- Страница `/<id>` открывается только для существующей, не истёкшей конференции. Проверка выполняется и при входе через signalling.
- Ответная ссылка строится из адреса HTTP-запроса: при работе за reverse proxy проверьте внешний URL.

## TURN и развёртывание

Docker Compose запускает приложение и отдельный сервис `coturn`. TURN использует конфигурацию из `coturn/` и сеть хоста Linux: порты доступны непосредственно на сервере. Сервис автоматически перезапускается и получает из `.env` только настройки TURN.

Для совместимости с фиксированными credentials добавьте в `.env` (замените IP на публичный адрес сервера):

```dotenv
TURN_HOST=176.119.158.186
TURN_URL_UDP=turn:176.119.158.186:3478?transport=udp
TURN_URL_TCP=turn:176.119.158.186:3478?transport=tcp
TURN_USERNAME=admin
TURN_PASSWORD=<сильный пароль>
```

Сгенерировать пароль можно командой `openssl rand -hex 32`. В этом режиме оставьте `TURN_SECRET` незаданным. Приложение и coturn получают одинаковые credentials из `.env`; пустой пароль не допускается.

Для временных credentials вместо фиксированного пользователя задайте:

```dotenv
TURN_HOST=176.119.158.186
TURN_SECRET=<случайный секрет из openssl rand -hex 32>
TURN_URLS=turn:176.119.158.186:3478?transport=udp,turn:176.119.158.186:3478?transport=tcp
```

`TURN_SECRET` имеет приоритет над фиксированным пользователем в обоих сервисах. Приложение выдаёт браузеру временные credentials через `/ice-config.js` с `Cache-Control: no-store`. Если не заданы ни секрет, ни непустые имя и пароль, coturn завершится с ошибкой настройки, а приложение будет использовать только STUN.

Откройте **3478 UDP/TCP** и **49160–49200 UDP** в системном firewall и firewall провайдера. При NAT задайте `EXTERNAL_IP=<публичный IP>/<приватный IP>` и настройте прямое перенаправление этих портов. HTTP reverse proxy не заменяет доступ к TURN-портам.

Если ранее запускали TURN вручную через `docker run`, остановите прежний контейнер перед запуском Compose-сервиса, чтобы освободить порт 3478.

Запустить только TURN, не пересоздавая приложение:

```sh
docker compose up -d coturn
docker compose logs --tail=100 coturn
```

Compose монтирует `${APP_DATA_DIR:-./persistent-data}` с хоста в `/app/data`. Сохраняйте `DB_PATH` внутри `/app/data` (относительный путь `./data/...` тоже подходит). Имя существующей базы менять не нужно: например, для `./data/ahey.db` оставьте именно это значение.

**Миграция существующего контейнера без volume:** сначала сохраните его каталог данных. Во время копирования приложение будет остановлено; это позволяет скопировать SQLite вместе с WAL/SHM без параллельной записи. Выполняйте команды из каталога проекта:

```sh
mkdir -p persistent-data &&
app_data_dir=$(mktemp -d "$PWD/persistent-data/app.XXXXXX") &&
docker stop ahey-app &&
docker cp ahey-app:/app/data/. "$app_data_dir/" &&
tar -C "$app_data_dir" -czf "$app_data_dir.backup.tgz" . &&
printf 'APP_DATA_DIR=%s\n' "$app_data_dir"
```

Убедитесь, что копирование завершилось успешно и файл существующей базы находится в новом каталоге. При ошибке не пересоздавайте контейнер: `docker start ahey-app` вернёт старое приложение. Установите в `.env` `APP_DATA_DIR` равным напечатанному пути и сохраните прежний `DB_PATH`. Команды также сохраняют отдельную резервную копию в `<APP_DATA_DIR>.backup.tgz`. Для данных вне `/app/data` сначала перенесите соответствующий каталог отдельно.

Затем примените настройки обоих сервисов:

```sh
docker compose up -d --build
```

Обычный `docker compose restart` не применяет изменения `.env`. Обновите страницу встречи и проверьте `/ice-config.js`: должны присутствовать TURN URL, username и credential. Затем проверьте звонок между разными сетями; наличие конфигурации ещё не подтверждает доступность ретрансляции.

TLS по умолчанию отключён. Для TLS добавьте в Compose-сервис coturn монтирование сертификата и ключа, передайте `TLS_CERT` и `TLS_KEY` с путями внутри контейнера и откройте 5349 TCP. Объявляйте `turns:<имя из сертификата>:5349?transport=tcp` в `TURN_URLS` только после настройки TLS.

## Проверки и ограничения

```sh
npm test
```

Тесты покрывают изоляцию конференций, передачу сигналов только между участниками одной комнаты, очистку после отключения, отсутствие лимита в четыре участника и генерацию TURN credentials.

Локально проверены API/SQLite, WebSocket-соединения, видеосвязь между вкладками и выход из звонка. Интерфейс проверен на настольной и мобильной ширине. Качество звука, демонстрацию экрана на целевых устройствах и TURN во внешних сетях нужно проверить в окружении развёртывания.

Mesh не заменяет SFU для больших встреч. Если страница оставалась открытой до входа дольше `TURN_TTL`, обновите её для получения новых credentials. Ограничения использования публичной выдачи TURN credentials и квоты на ретрансляцию настраиваются при эксплуатации.
